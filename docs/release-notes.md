# 릴리스 노트

사용자에게 보이는 동작이 바뀌는 변경을 기록한다(계획: [refactoring-plan.md](refactoring-plan.md) §5). 최신이 위에 온다.

## 2026-09-24 — 종목명 5개 추가

`config.TICKER_NAMES`에 다음 5개 국내 ETF의 한글명을 등록했다(연금계좌 자산배분 리서치 포트폴리오를 가져와 쓰면서 필요해짐). 이 종목들은 이제 yfinance API 보완 없이 바로 한글명이 표시된다.

| 티커 | 종목명 |
|---|---|
| 069500.KS | KODEX 200 |
| 305080.KS | TIGER 미국채10년선물 |
| 132030.KS | KODEX 골드선물(H) |
| 114260.KS | KODEX 국고채3년 |
| 329200.KS | TIGER 리츠부동산인프라 |

## 2026-09-22 — 등록되지 않은 종목명을 yfinance로 보완

- `config.py`의 `TICKER_NAMES`(국내 ETF 6종)에 없는 티커를 표에 추가하면(예: 미국 상장 ETF를 백업 JSON으로 가져온 뒤 종목 추가) 예전에는 종목명이 항상 `(미등록)`으로 나왔다. 이제 yfinance에서 받은 이름(`longName`, 예: "Vanguard Total Stock Market ETF")을 대신 보여준다. 이름을 못 받으면 계속 `(미등록)`이다.
- 국내 종목은 그대로 `config.py`의 한글명을 우선 쓴다(yfinance는 국내 종목도 영문명만 준다).
- 같은 티커의 이름은 하루 동안 캐시한다(가격과 달리 이름은 자주 바뀌지 않음). 이름을 못 받은 경우도 하루 동안 재시도하지 않는다(매번 API를 부르지 않기 위함).
- pykrx 등 KRX 데이터를 쓰는 방식은 검토했으나(2026-09부터 KRX 포털이 로그인을 요구하도록 바뀌어 계정 자격증명이 추가로 필요해짐) 채택하지 않았다.

## 2026-09-22 — 화면 구조 정리 (리팩토링 단계 5)

계산 결과는 바뀌지 않는다. 화면 배치와 표시만 정리됐다.

- **탭1(자동 최적화) 설정이 왼쪽 사이드바에서 탭 안으로 옮겨졌다.** 사이드바에는 이제 로그인한 계정 정보만 남는다. 다른 탭을 볼 때 탭1 설정이 계속 보이던 것이 없어진다.
- **탭1의 "자산 배분" 표에도 종목명이 함께 표시된다**(전에는 탭1만 티커만 보이고 탭2는 종목명이 있었다). "추천 매수 수량" 표에도 종목명이 추가됐다.
- 성과 차트(가치 추이·낙폭·수익률 분포)와 상관관계 히트맵의 제목이 한국어로 통일됐다(전에는 영어와 한국어가 섞여 있었다).
- `app.py`(초기 단일 페이지 버전, 로그인·저장 기능 없음)를 더 이상 배포하지 않는다. 실제 서비스는 계속 `app_advanced.py`를 쓴다.

## 2026-09-22 — 저장소 형식 검증 (리팩토링 단계 4)

눈에 보이는 화면 동작은 바뀌지 않는다. 저장 파일이 손상되었을 때의 동작만 달라진다.

- 저장된 JSON 파일이 손상되었거나(예: 전송 중 잘림) 형식이 어긋나면, 예전에는 알 수 없는 오류로 앱이 죽을 수 있었다. 이제는 "저장된 데이터가 손상되었습니다" 같은 원인이 드러나는 오류를 보여준다.
- 저장 파일에 `schema_version`이라는 항목이 새로 추가된다(직접 JSON 파일을 열어보면 보인다). 기존 파일에는 없어도 계속 읽히고, 다음에 저장할 때 자동으로 채워진다. 사용자가 따로 할 일은 없다.
- 여러 명이 동시에 "현재 구성 저장"을 눌러 저장소에 아직 없던 첫 데이터 브랜치를 만들 때 생기던 드문 경쟁 상황을 완화했다.

## 2026-09-22 — 성과 지표 계산 수정 (리팩토링 단계 3)

### 숫자가 달라지는 것

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 총수익률·연환산 수익률·변동성·샤프 | 백테스트 시작일의 **첫 거래일 수익률이 계산에서 빠졌다**(가격 100→110→110→121, 실제 +21%인데 +10%로 계산됨) | 시작일을 초기 자본으로 하는 시점을 시계열 맨 앞에 두고, 그다음 거래일부터 수익률을 반영한다. 실제 +21% 예시가 정확히 +21%로 계산됨 |
| 백테스트 결과표(가치 추이 차트 등)의 행 수 | 가격 데이터 일수보다 1일 적었다 | 가격 데이터와 같은 일수(시작일 포함) |
| 샤프 지수 | 포트폴리오가 거의 매일 똑같은 비율로만 움직이면(변동성이 부동소수 오차 수준, 약 1e-17) 계산상 `2.8×10^15` 같은 무의미한 값이 나올 수 있었다 | 변동성이 사실상 0으로 보이면 **"정의 안 됨(변동성 0)"**으로 표시한다 |

샤프 지수 라벨을 "샤프 지수 (무위험수익률 0% 가정)"으로 바꿔 계산에 깔린 가정을 밝혔다.

### 바뀌지 않는 것

저장 데이터 형식, 로그인, 시세 캐시·분석 구간 표시(단계 2), 리밸런싱 가이드의 계산 방식.

## 2026-09-22 — 결측·정렬 정책과 시세 캐시 (리팩토링 단계 2)

여러 종목의 가격 기간이 다를 때의 처리를 **명시적인 정책**으로 바꾸고, 시세 조회를 캐시했다. 결측이 없는 데이터에서는 계산 결과가 달라지지 않는다(pandas 2.3.3과 3.0.6에서 같은 결과 확인).

### 화면에 새로 보이는 것

- 백테스트·자동 최적화 결과 위에 **"분석 구간: 시작 ~ 끝 (N거래일)"** 을 표시한다.
- 상장이 늦은 종목 때문에 시작일이 요청보다 늦어지면 **어떤 종목 때문인지와 그 종목의 첫 가격일**을 안내한다(이전에는 조용히 잘렸음).
- 일부 종목의 가격이 없는 거래일을 제외했다면 **몇 거래일을 제외했는지** 경고한다.

### 숫자가 달라질 수 있는 경우

| 상황 | 이전 | 이후 |
| --- | --- | --- |
| 한 종목의 가격이 중간에 하루 비어 있음(거래 정지 등) | 결과가 **pandas 버전에 따라 달랐다**(배포 버전은 앞 값으로 채워 그날 수익률 0%, 최신 버전은 그 행을 통째로 제거) | **그날을 제외**하고 그 전후 가격으로 수익률을 계산한다(앞 값으로 채우지 않음). 버전과 무관하게 같은 결과 |
| 종목의 상장이 늦음 | 가장 늦게 시작한 종목 기준으로 잘렸으나 표시가 없었음 | 같은 구간을 쓰되 **표시와 안내가 생김** |
| 자동 최적화(max Sharpe, min volatility) | 결측이 있는 표를 그대로 사용 | 공통 관측 구간으로 맞춘 표로 계산 |
| 포트폴리오 비교에서 가격을 받지 못한 종목이 있음 | 그 포트폴리오만 "데이터 부족"으로 제외 | 종목명을 밝히는 오류로 **비교 전체가 중단**된다(가격을 받지 못한 종목을 조용히 넘기지 않기 위해) |

### 시세 캐시로 달라지는 동작

- 같은 종목·기간의 과거 시세는 **30분**, 현재가는 **5분** 동안 다시 내려받지 않는다. 그 사이에 화면을 다시 조회하면 **최대 5분(현재가)/30분(과거)까지 이전 데이터**가 보일 수 있다. 모든 탭과 사용자가 캐시를 공유해 Yahoo 요청 수가 줄어든다(티커 순서가 달라도 같은 종목 집합이면 공유).
- 시세 조회 실패는 캐시하지 않는다.

### 바뀌지 않는 것

저장 데이터 형식, 로그인, 성과 지표 계산식(단계 3에서 별도 수정 예정), 화면 기본값(기간·자본·주기는 `config.py`로 옮겼을 뿐 값은 같음).

## 2026-09-22 — 입력 검증과 시세 조회 실패 처리 (리팩토링 단계 1)

잘못된 결과를 조용히 내던 곳을 오류로 바꾸고, 가격 기준과 종료일 처리를 바로잡았다. **일부 화면의 숫자가 이전과 달라진다.**

### 숫자가 달라지는 것

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 리밸런싱 가이드의 가격 기준 | 직전 거래일 종가(끝에서 두 번째 행) | **마지막 사용 가능한 거래일 종가**. 화면에 "가격 기준: 마지막 거래일 종가 (날짜)"를 표시하고, 종목마다 기준일이 다르면 경고 |
| 종료일 | 선택한 종료일 당일 데이터가 결과에서 빠짐(Yahoo의 종료일이 배타적이기 때문) | **선택한 종료일까지 포함**. 실제 확인: 종료일을 2026-09-22로 두면 마지막 행이 2026-09-22 |

가격 기준 변경 예시(가상 수치): 종목 A 100주, 직전 종가 10,000원 → 마지막 종가 10,200원이면 평가액이 1,000,000원에서 1,020,000원으로 바뀌고, 필요 현금과 매수/매도 수량도 이에 따라 달라진다. 백테스트 기간의 마지막 하루가 추가되므로 총 수익률·최대 낙폭도 소폭 달라질 수 있다.

### 조용한 오류가 명시적인 오류로 바뀐 것

| 상황 | 이전 | 이후 |
| --- | --- | --- |
| 보유·목표 종목의 가격이 없음/0/NaN (리밸런싱 가이드) | 그 종목을 0원으로 계산해 **다른 종목을 잘못 매도하라고 안내**(재현: A·B 각 10주에서 B 가격이 없으면 A 5주 매도 안내) 또는 알 수 없는 오류 | 종목명을 밝히는 오류를 표시하고 **매매 안내표를 만들지 않음** |
| 사용자 정의 백테스트에서 가격 데이터를 받지 못한 종목 | 그 종목을 **조용히 빼고** 다른 구성으로 계산 | 종목명을 밝히는 오류 |
| 비중·목표 비중 합계 0, 음수, 숫자 아님 | 결과가 `NaN`이 되거나 `ZeroDivisionError`, 음수는 공매도로 계산 | 원인을 설명하는 메시지 |
| 시작일이 종료일보다 늦음, 종료일이 오늘 이후 | 원인 불명의 빈 결과/오류 | 날짜를 밝히는 메시지(서버와 사용자의 날짜가 하루 어긋날 수 있어 하루 뒤까지는 허용) |
| 가격 데이터가 비었거나 거래일이 부족(3거래일 미만) | `AttributeError`, `KeyError('Date')` 등 | "가격 데이터가 비어 있습니다", "거래일이 부족합니다" 등 |
| 시세 조회 실패, 없는 티커 | 빈 dict로 숨기거나 일반 오류 | "시세를 가져오지 못했습니다: …" (종목명 포함) |

### 그 밖의 변경

- 티커 입력의 공백, 빈 항목, 중복을 자동 정리한다.
- 오류 메시지를 세 종류로 구분한다: 입력 오류(그대로 표시), 시세 조회 오류("시세를 가져오지 못했습니다"), 그 밖의 예상하지 못한 오류("예상하지 못한 오류가 발생했습니다").

### 바뀌지 않는 것

- 저장된 포트폴리오·보유 수량의 형식과 데이터, 로그인, 포트폴리오 비교.
- 정상 입력에서의 성과 지표 계산식(첫 거래일 수익률 누락과 샤프 계산은 단계 3에서 별도 릴리스로 수정 예정).
